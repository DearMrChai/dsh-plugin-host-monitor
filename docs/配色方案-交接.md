# dsh-plugin-host-monitor — 配色方案交接文档

> 状态：**方案 A 已落地**（已应用到 `lib/client.js`，见「5. 落地注意事项」逐项实现）；方案 B/C 保留为备选，见第 3 节。
> 目标：随 DSH 深/浅外观两套色板；各模块统一、克制不乱色；修掉「字体全变 CPU 主色」与「GPU/推理进度条同色、CPU 不同」两个问题。

---

## 1. 当前问题根因（先定位，再配色）

| 表象 | 根因 | 后果 |
|---|---|---|
| “字体均为 CPU 板块主色” | 正常(ok)状态的**数值文字**也用了 `statusCol(ok)=绿色`（`lib/client.js` 的 `mRow` 数值按状态色渲染），而 CPU 身份色恰好也是绿 | 所有正常指标数值都是绿 → 全界面像被 CPU 色盖住 |
| “GPU/推理进度条一样、又和 CPU 不同” | 进度条填充一律取 `statusCol(level)`，ok 态三模块**是同一个绿**；只有标题/左边条用了各自身份色 | 模块间进度条颜色无法区分，视觉上“一样 / 不一致”并存 |
| 颜色语义混乱 | “状态色”与“模块身份色”混用在同一元素上 | ok 被当通用绿，身份色形同虚设，双色板意义不明确 |

**一句话**：错误在于把「正常=绿」当成了通用基线，而模块身份色没有真正落到进度条/文字上。

---

## 2. 设计原则（本次配色必须遵守）

1. **角色分工三色系**：
   - **中性**（normal）：正常数值 / 标签 → 主题文字色，**不再泛绿**。
   - **模块身份色**（identity）：模块标题、左边条、sparkline、**ok 态进度条填充** → 每模块一色。
   - **语义色**（semantic）：超阈值预警 warn / 危险 danger → **跨模块统一**（全界面同一个琥珀、同一个红）。
2. **每模块一整套一致**：GPU 卡内所有身份色元素都是 GPU 蓝；推理青；CPU 绿。模块内不混入别的身份色。
3. **克制**：正式方案身份色 3 个 + 语义色 2 个 + 中性，≈5 类角色色，绝不“彩虹”。
4. **双主题**：深色（低亮度背景）用偏亮/饱和色；浅色（白底）用**降饱和、加深**到可在白底上可读的色。两套在 `THEME.light/dark` 内独立定义，随 `--dsw-alias-bg-base` 亮度自动切换（现有 `pickTheme()` 已实现）。
5. **正向指标例外**：仅“好=绿”的正负型指标（如 MTP 接受率 ≥70、连接正常、推理状态 ok）才用绿；温度/使用率这类**单调高=坏**的指标，正常态一律中性。

## 3. 多方案对比（预备阶段）

| 维度 | A · 模块身份色 + 中性正文（**推荐**） | B · 单色系深浅（极素） | C · 语义渐变（Grafana/Netdata 风格） |
|---|---|---|---|
| 每个模块的身份 | 强（标题/左边条/sparkline/ok 进度条各自一色） | 弱（仅左边条+标题文字，进度条不做彩色） | 中（进度条从身份色渐变到语义色） |
| 进度条区分度 | 三模块三色，一眼可辨 | 全同色，靠布局辨 | 渐变色，科技感但不够“素” |
| 字数/色彩数量 | 3 身份 + 2 语义 + 中性 ≈5 | ≈2 语义 + 中性 ≈3（最朴素） | 3 身份渐入 + 2 语义 ≈6 |
| 修“全 CPU 绿” | ✅ 正常正文中性化 | ✅ | ✅ |
| 修“进度条同色混乱” | ✅ 每模块一色 | 削弱（不区分） | ⚠️ 渐变后仍有同感 |
| 简洁清晰 | ★★★★ | ★★★★ | ★★★ |
| 实现成本 | 改 `mRow` 默认色 + `bar` ok 态取身份色 | 改最大 | 中 |
| **结论** | **推荐**（平衡清晰度与模块区分） | 备选（若“极素”优先） | 不推荐（科技感>素雅） |

**推荐 A** 的理由：它同时满足你两条硬要求——正文不再全是 CPU 绿（正常文字中性化），且每模块进度条各一色（身份色落位），颜色总数克制、不杂乱。

## 4. 推荐方案 A 的完整色板（dark / light 两套）

### 4.1 角色色表

| 角色 | Dark（深色） | Light（浅色/白底） | 用途 |
|---|---|---|---|
| 中性 主文字 | `var(--dsw-alias-label-primary)` | 同左 | 正常数值 |
| 中性 次文字 | `var(--dsw-alias-label-secondary)` | 同左 | 标签 |
| 中性 辅文字 | `var(--dsw-alias-label-tertiary)` | 同左 | 次要/占位 |
| 身份 · GPU | `#5aa7ff`（亮蓝） | `#2f6fbf`（深蓝） | GPU 标题/左边条/进度条 ok/sparkline |
| 身份 · 推理 | `#45c3e0`（青） | `#0e7a9d`（深青） | 推理 标题/左边条/进度条 ok/sparkline |
| 身份 · CPU | `#4dc9a0`（绿） | `#158a63`（深绿） | CPU 标题/左边条/进度条 ok/sparkline |
| 语义 · warn | `#f5a623`（琥珀） | `#b45309`（深琥珀） | 预警：数值/进度条/闪烁（跨模块统一） |
| 语义 · danger | `#ff5a5f`（红） | `#d92d20`（深红） | 危险：数值/进度条/闪烁/圆点脉冲（跨模块统一） |
| 语义 · ok（仅正负型） | `#3ad49a`（绿） | `#128a5e`（深绿） | MTP≥70、连接正常、推理 id 等“好” |

> 说明：CPU 身份 `#4dc9a0/#158a63` 与 ok 语义绿 `#3ad49a/#128a5e` 刻意**不同**——避免 CPU 身份色和“正常绿”混为一谈，正是修“全 CPU 绿”的关键之一。

### 4.2 元素 → 颜色映射（A 方案的落地规则）

| 元素 | 正常 | 预警 | 危险 |
|---|---|---|---|
| **数值文字**（温度/使用率/显存/速率/时延…单调高=坏） | 中性主文字 | 语义 warn | 语义 danger |
| **进度条填充** | **所属模块身份色** | 语义 warn | 语义 danger |
| **模块标题 / 左边条 / sparkline** | 所属模块身份色（不变） | 身份色（不变，闪烁另表达） | 身份色（不变） |
| **卡闪烁（边框/光晕）** | 无 | 语义 warn | 语义 danger |
| MTP 接受率、连接点、推理状态（正负型） | 语义 ok（绿=好） | 语义 warn | 语义 danger |
| 收起信息条数值 | 中性 | warn/danger 同上 | — |
| 页头/收起态 连接点 | 语义 ok（绿） | 语义 warn | 语义 danger |

### 4.3 一个模块内的示例（GPU 卡，A 方案）

```
┌ GPU0 · NVIDIA GeForce RTX 2080 Ti     61℃   ← 标题=身份蓝，温度超90→红
│ 使用率          45%                     ← 正常=中性字；进度条(fill)=身份蓝
│ ══╦═════════                    (sparkline=身份蓝)
│ 显存   6/11G                     ← 进度条 ok=身份蓝
╰──────────────────────────────
```
- 正常时卡片整体是“中性字 + 蓝系进度条/标题”；任何超 90℃ → 温度值、进度条、边框全部切到**同一个红**。

## 5. 落地注意事项（交接给实现）

1. `mRow(label, value, level, …)` 的数值颜色改：`normal → P.textPrimary`（只有 `warn/danger/offline` 用语义色；正负型场景单独传 `ok`）。
2. `bar(pct, level, …)`：ok 态填充色从 `statusCol(ok)` 改为**模块身份色**——`bar` 需额外接收模块身份色（或拆 `mBar(label, value, level, pct, moduleId, marks)`）。
3. 模块身份色别用于正文（只用于 标题/左边条/sparkline/ok 进度条）。
4. `THEME.light/dark` 各存两套：`identity{...}`（gpu/vllm/cpu）+ `status/warn/danger` + 中性用 DSH 变量。
5. `pickTheme()` 已按背景亮度切双色板，无需改。
6. 验证清单：正常态任何板块不再出现“成片绿字”；GPU/CPU/推理三卡进度条三色可辨；切深/浅主题后颜色均可读。
7. 完成后更新 README「UI 设计要点」与日志记录，并把本方案文档归档到项目 `docs/`。
